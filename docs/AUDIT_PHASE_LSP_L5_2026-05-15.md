## VERDICT

**PROCEED to L6: YES**

**Open P0 count: 0**

L5's central safety promise — that `rename`'s `WorkspaceEdit` is **structurally** unable to touch a non-reference token (string-literal substring, comment word, different-scope same-spelled symbol) — holds against the code, not merely against a passing test. The exclusion is genuinely *by construction*, resting on two independently verified invariants: (1) `ReferenceIndex::build` only ever consults `SyntaxKind::Ident` tokens routed through L3's single `resolve_at` classifier + `SymbolTable::resolve_*` — no string/`text()`/`==`-on-identifier-text comparison exists anywhere in `refs.rs`; (2) symbol identity is a `SymbolKey = (kind, machine-index, decl Span)` whose `decl` Span comes from the `SymbolTable`, so two same-spelled tokens in different scopes land in provably different `HashMap` buckets. `prepareRename`'s reject set is complete and surfaced up-front as JSON-RPC errors; `rename` independently re-validates (defence-in-depth); collisions and invalid identifiers over-reject with no edit; the file-extern-decl-zero-uses boundary is conservative-correct (declines, never fabricates). §11.36's classifications are accurate against HEAD. No L6 scope creep, no silent no-op handlers, `#![forbid(unsafe_code)]` intact at both `fsm-lsp` roots. Findings are two **P3** doc-precision nits and the standard pre-existing **P2** doc-reconciliation debts (DRIFT-1/DRIFT-2, tracked, not introduced or relied upon by L5). None blocks L6.

## Verified-clean (positive evidence)

- **The keystone correctness invariant — `resolve_at` returns `None` on a declaration-name ident — is structurally guaranteed, not just tested.** `resolve.rs::classify` (184-401) dispatches on the *parent node `SyntaxKind`* of the ident. A decl-name ident's parent is its decl node (`STATE_DECL`/`EVENT_DECL`/extern/context-field decl) or `MACHINE_DECL`; **none of these is a `classify` arm** → falls to `_ => None` (399). `ENTRY_POINT_DECL` index-0 (a pseudo-state's own declared name) is *explicitly* `None` (366-370). The analyzer's `checks/name_resolution.rs` likewise only inspects *use* positions (transitions/guards/expr/raise/send/defer/call/initial-targets) — it never resolves a decl-name ident as a reference, so `resolve_at` mirroring it inherits this. Unit test `resolve.rs::declaration_site_is_not_a_use_site` (633-644) pins it. **Consequence:** the decl occurrence is discovered *only* structurally via `collect_decl_name_tokens`, and the use-loop can never double-count it (plus the belt-and-braces `already_decl` guard, `refs.rs:208-217`). The whole "decl + semantic uses, nothing else" model is sound.
- **`first_ident_in` is byte-consistent with the recorded name.** `symbol_table.rs` derives every entry's name via the typed `.name()` accessor (e.g. `StateDecl::name` = `ast::first_ident`, `ast/state.rs:31-33`) and its span via `span_of(node.syntax())` = the *whole decl subtree* (`util.rs:148-151`). The decl subtree is keyword-prefixed (`state`/`event`/…); the name is the first `Ident` after the keyword. `refs.rs::collect_decl_name_tokens::first_ident_in` (569-579) finds the first `Ident` (document order) fully contained in that span — which is exactly that name token. An `@id("…")`/`@some_id` annotation is wrapped *inside* the decl node (`ast/top_level.rs:202-207`) but emits a `StringLiteral` or `StableId` token — **never an `Ident`** (`ast/top_level.rs:348-358`) — so it cannot be mistaken for the decl name even though it precedes it within the span. Nameless decls (resilient parser on broken input) yield `None` → no panic, no guessed range (`refs.rs:563-579`).
- **Single-file containment is structural.** Every served range is a byte range of the same parsed buffer; `references` sets `Location.uri = uri.clone()` for all (`references.rs:55-58`), `rename` keys the single `changes` map by the request `uri` (`rename.rs:95-101`). Cross-file is impossible by construction, matching Doc 26 §4.6/§9.
- **One position converter preserved (DRIFT-2 boundary untouched).** All ranges go through L1's `LineIndex::range`/`offset` in the negotiated encoding (`references.rs:57`, `rename.rs:91`, `server.rs:528,576,617`). No second converter introduced by L5. L5-f proves correctness under both UTF-8 and UTF-16 on a multibyte fixture.
- **No L6 scope creep / no silent no-op handlers.** `capabilities/mod.rs` exposes only through L5 (`references`, `rename`); `server.rs:26-29` + `mod.rs:34-39` explicitly decline to stub semanticTokens/codeAction/inlayHint (the `workspaceSymbol`-unadvertised precedent, Doc 00 §11.33(5)). Capabilities advertised in `initialize` (`server.rs:236-247`) exactly match implemented behaviour (`references_provider` + `RenameOptions{prepare_provider:true}`). `prepareRename`/`rename` refusals are loud JSON-RPC errors, never silent `Ok(None)`.
- **`#![forbid(unsafe_code)]` intact at BOTH `fsm-lsp` compilation roots:** `lib.rs:100` and `main.rs:16`. Workspace 10/10 claim holds at crate granularity.
- **One analysis feeds all; L1–L4 byte-unchanged.** `server.rs` every handler does a single `analyze()` then projects; `ReferenceIndex::build` consumes that run's `symbol_table` + parse (no second pass). §11.36(5)'s "755 = 739 baseline + 16 new L5 (9 unit + 7 acceptance)" is consistent with the green baseline and the test-count I observed (refs.rs 4 + references.rs 2 + rename.rs 3 = 9 unit; L5-a..g = 7 acceptance).
- **Test fixtures are genuine adversarial inputs** (not toy): `l5_safety.fsm` really contains `"Moving to next floor"` (string), a comment "mentions Moving by name", and a second machine `Crane` with its own `state Moving` — exactly the three risk-2 corruption classes. `l5_non_ascii.fsm` puts a 🚀+Cyrillic block comment on the same line as a `Target` use, forcing real intra-line UTF-8↔UTF-16 column math.
