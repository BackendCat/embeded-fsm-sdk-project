## 0. Executive summary (read this first)

**Verdict: the `editors/vscode/**` surface is fundamentally sound — a disciplined, Zero-Legacy, well-tested extension. It does NOT need a yardstick-driven refactor.**

The evidence is unambiguous: ~8,410 lines of TypeScript across a small, domain-cohesive `src/` tree; `tsc` `strict` + `noUnusedLocals`/`noUnusedParameters`/`noImplicitReturns`/`noFallthroughCasesInSwitch` on the Node program **and** a separate strict DOM-lib tsconfig for the Webview; **zero `: any`/`as any`/`<any>` in non-test `src/`**; **zero `console.*` in non-test `src/`**; exactly **two narrowly-scoped `eslint-disable`s, both in test files** with a stated reason; WHY-focused comments throughout (the project comment doctrine); and an Extension-Host (`@vscode/test-electron`) suite of ~35 tests across V1–V6 + W-A1 that asserts **observable editor state against a real `fsm`-binary differential oracle**, not symbol-presence — the project's structural realisation of the CellWar "R6 — Playwright is the only truth" standard *in the correct primitive for a VS Code extension* (a real headless Extension Host, not a browser).

Against the CellWar/EdgeForge yardstick there are real deltas (no `prettier`, a legacy `.eslintrc.json` on ESLint 8 vs the yardstick's flat ESLint-9 config, no feature-slicing, no Playwright). **Most are correctly NOT worth chasing here** and are dispositioned won't-do / defer-tracked with a written rationale — a disciplined "this is fine, here's why" is a first-class outcome of this wave. **Exactly two findings earn fix-in-v1.5**, both because they harden the epic's *headline* surface (the verify UX) or remove a real day-to-day cost, and one of those is the genuine R6-standard gap this wave was scoped to find:

- **C1-F1 (fix-in-v1.5, the headline) — the A2 LSP-live verify command (`fsm.verifyLive`) has NO client-side Extension-Host test.** A1's CLI-spawn path is host-tested to byte-equality (`verify.test.ts`), and the A2 server seam is differential-tested at the Rust layer (`crates/fsm-lsp/tests/verify_lsp_acceptance.rs`), but **nothing drives the registered `fsm.verifyLive` command through a real editor** — the debounce / large-FSM ceiling / `State.Running` honest-degrade / JSON-RPC-error-verbatim branches in `verify.ts:355–540` are host-untested. This is exactly the R6 gap C2 was pre-scoped to close (Doc 31 §1 W-C2: "the Playwright/host verify-UX E2E that hardens A1/A2").
- **C1-F2 (fix-in-v1.5) — adopt `prettier` (the yardstick's mechanical-formatting layer).** Real recurring cost (hand-formatting + style nits in review) for a near-zero, byte-mechanical one-time change; it is the one yardstick hygiene item with a genuine value/cost case on a TS surface that is about to be Marketplace-shipped.

Everything else — flat ESLint-9 migration, feature-slicing, `lint-staged`/`husky`, `madge`, `openapi-typescript`, the `makeNonce` CSPRNG nit (owned by **B1**, not C1 — file-disjoint) — is dispositioned **won't-do-with-rationale** or **defer-tracked**, each with the evidence-cited reason in §3. No P0. No ship-blocker. The bar for fix-in-v1.5 was a *real* value/cost case, deliberately not yardstick-cargo-cult.

## 2. What is already at or above the yardstick (the leave-and-explain evidence base)

This section records, with `file:line`, why the surface is "fundamentally sound" — so the won't-do dispositions are evidenced, not asserted.

- **Strictness ≥ yardstick.** `tsconfig.json:` `strict`, `noUnusedLocals`, `noUnusedParameters`, `noImplicitReturns`, `noFallthroughCasesInSwitch`, `forceConsistentCasingInFileNames`. The Webview is **not** left untyped: `tsconfig.webview.json` is a *separate* strict program with the `DOM` lib (its header documents exactly why — browser context, esbuild owns bundling, `noEmit` type-gate wired into `typecheck`/`pretest`). This is the same "split tsconfig by runtime profile" idea the yardstick's project-refs encode, applied at the granularity an extension needs. (CellWar adds `noUncheckedIndexedAccess`; the extension does not — a single, minor, non-blocking strictness delta, not worth a standalone v1.5 change; folded into the §4 v1.6 FE-hygiene note.)
- **No `any`, no `console`, minimal disables.** `grep ': any|as any|<any>' src --include=*.ts | grep -v /test/` ⇒ **∅**. `grep 'console\.' src --include=*.ts | grep -v /test/` ⇒ **∅**. Total `eslint-disable`/`@ts-ignore` in `src/` = **2**, both in `src/test/suite/grammar.test.ts:67–68` (a contained `require()`-based grammar-fixture read, reasoned in-line) and one `no-console` line-disable in a V6 test. This is *cleaner* than a typical CellWar feature slice.
- **The Extension-Host suite is the R6 standard in the right primitive.** `src/test/runTest.ts` launches a real headless VS Code; `src/test/suite/*.test.ts` (V1 diagnostics, V2 grammar, V3 commands, V4 diagram, V5 tree, **W-A1 verify**) assert *observable editor state* against a **differential oracle = the real `fsm` binary spawned in-test** (`verify.test.ts:51 cliVerify`, `:201 assert.deepStrictEqual(witnessLines, oracleWitness)`). Every suite header explicitly **rejects symbol-presence as acceptance** (e.g. `verify.test.ts:1` "NOT symbol-presence … the P0-1 lesson"). This *is* the CellWar "R6 — the only truth" philosophy, realised with `@vscode/test-electron` (the correct host harness for an extension; Playwright drives browsers, not a VS Code Extension Host).
- **Comment doctrine honoured.** Comments are WHY-focused and load-bearing (`verify.ts:7` the cardinal-invariant block; `tsconfig.webview.json` header; `esbuild.mjs` two-bundle rationale; `.vscodeignore` the duck-principle exclusion logic) — matching the project's TS WHY-only comment doctrine, not noise.
- **Bundling + packaging discipline.** `esbuild.mjs` (one fast bundler, no webpack tree — externalises `vscode`, bundles the client; a separate browser-IIFE webview bundle for the strict CSP). `.vscodeignore` produces a lean-but-real VSIX (excludes `src/`/`node_modules`/fixtures, ships `dist/`+`bin/`). The V6 suite (`suiteV6/bundled.test.ts`) asserts the *packaged* VSIX is real (Rule-2 bundled-binary round-trip), not "vsce exited 0".

The conclusion that follows: this is not a surface with a quality deficit the yardstick would remedy. It is a surface where the yardstick's *philosophy* (real-oracle host testing, strict types, honest verdicts) is already met, and the yardstick's *specific tooling* (flat ESLint-9, prettier, feature-slicing) is a set of independent choices to judge on merit — which §3 does.

## 3. Dispositions in full (the C2 contract)

### 3.1 fix-in-v1.5 set (the C2 remediation backlog — ordered; exactly what C2 executes)

> Ordered by value-per-cost. Each carries its acceptance. This is the **only** work C2 performs (Doc 31 §1 W-C2: "execute ONLY the C1 findings dispositioned fix-in-v1.5").

1. **C1-F1 (+ folded C1-F9) — Extension-Host E2E for the A2 live-verify UX (the headline; the R6 gap).**
   - **What:** add a `verify.test.ts`-sibling Extension-Host test (or extend `verify.test.ts`) that drives the **registered `fsm.verifyLive` command** end-to-end through the real headless host: (a) a clean fixture → live verdict surface == the `fsm verify --json` oracle (reuse `cliVerify`/`resolveRealBinaries`); (b) a deadlocking fixture → the witness rendered by the live path byte-equals the oracle; (c) **the INCONCLUSIVE-not-VERIFIED honesty asserted *through the command*, not only `renderVerifyReport`** (folds C1-F9 — drive it via a naturally-inconclusive fixture or the configurable bound); (d) the `State.Running`-absent / large-FSM-ceiling branches degrade *honestly* (assert the honest message, never a fabricated clean verdict — `verify.ts:441`,`:430`).
   - **Acceptance (Doc 31 §1 W-C2 §5.4):** the live-verify-UX host test is **green**; it drives the *real extension* through the live path and asserts the witness list + the false-proven guard end-to-end in the host (not a renderer/unit mock). The differential oracle is the real `fsm` binary, mirroring `verify.test.ts`'s structural "editor === CLI" proof — extended to the A2 surface. Re-run under the §5 cold-quad JS lane.
   - **Why first:** it hardens the *epic's reason for existing* (the live verify UX); it is the genuine R6-standard gap (the live path is asserted only at the Rust layer today, never through the editor a user actually uses).

2. **C1-F2 — adopt `prettier`.**
   - **What:** add `prettier` (+ optionally `eslint-plugin-prettier`/`eslint-config-prettier`, or run prettier standalone to avoid coupling to the deferred C1-F3 lint migration — C2's choice, the lower-risk being standalone prettier given C1-F3 is deferred) + a `prettier.config.*` (the CellWar profile is a sane default: `printWidth:100, tabWidth:2, semi:true, trailingComma:"all"`); one mechanical `prettier --write src/` pass; add a `format`/`format:check` script. Isolate the mechanical reformat in **its own commit** (the v1.2 "byte-identity/mechanical-only" precedent) so the diff is review-trivial.
   - **Acceptance:** `prettier --check src/` is clean; the Extension-Host suite (incl. C1-F1's new test) still **green** post-reformat (no behavioural drift — formatting only); the reformat commit is mechanically verifiable (AST-equivalent, comments/strings unchanged).
   - **Why second:** highest-frequency papercut removed (review style-nits + hand-formatting) for the lowest one-time cost, on a surface that is about to be Marketplace-published (B1) where consistent formatting has external visibility.

### 3.3 won't-do-with-rationale (a first-class outcome)

- **C1-F5 — feature-slicing the `src/` tree.** The tree is already capability-cohesive (`commands/`, `diagram/`+`webview/`, `tree/`) and small; the `features/shared/app/pages/entities` shape solves *large React-SPA* navigation, which this ~8.4k-line Node extension does not have. A wholesale move would rewrite every import + re-baseline all 35 host tests' relative paths/fixture copies for **zero behavioural or navigational gain** — the precise "don't refactor a working surface for purity points" anti-pattern the brief forbids.

## 6. One-paragraph honest verdict

The `editors/vscode/**` surface is **fundamentally sound** — a disciplined, Zero-Legacy, strictly-typed extension whose Extension-Host suite already realises the CellWar "R6 — the only truth" philosophy in the correct primitive (a real headless VS Code + a real-`fsm`-binary differential oracle), with no `any`, no stray `console`, WHY-focused comments, and an honest verify UX. **The genuinely-worth-it deltas are exactly two:** (1) **C1-F1** — an Extension-Host E2E for the A2 *live* verify command (`fsm.verifyLive`), which today is asserted only at the Rust layer and never through the editor a user actually drives — closing this hardens the epic's headline surface and is the precise R6 gap C2 was pre-scoped to fill (it folds C1-F9, asserting the false-proven honesty guard end-to-end through the command, not just the renderer); and (2) **C1-F2** — adopting `prettier`, the one yardstick hygiene item with a real recurring-cost/near-zero-cost case on a surface about to be Marketplace-published. **Everything else is deliberately left:** the flat ESLint-9 migration and `madge` are real-but-modest and defer-tracked to a coherent v1.6 FE-hygiene batch rather than being churned onto the v1.5 Marketplace pass; the `makeNonce` CSPRNG fix is real but **B1 already owns it** (file-disjoint — recorded, not re-assigned); and feature-slicing, husky/lint-staged, and `openapi-typescript` are won't-do-with-rationale — feature-slicing is cargo-cult on a small cohesive tree, husky is a repo-root concern the project deliberately replaces with the cold-quad gate (and a yardstick reference, EdgeForge, also ships none), and there is simply no HTTP API for `openapi-typescript` to type. A working, well-tested surface should not be refactored for purity points; the two fixes that earn their place are the ones that harden what the epic ships.
