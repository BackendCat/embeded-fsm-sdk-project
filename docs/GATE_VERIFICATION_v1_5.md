### 4.2 Cold-quad method (§11.22) — **with the MANDATORY NOTE-1 `cargo clean -p` STEP 0 (binding v1.4+)**

§11.22 mandates a **cold from-source** green quad for a release tag (a warm shared-`CARGO_TARGET_DIR` can serve stale cross-worktree `-wt-`-baked-path test binaries; a warm pass is necessary-but-not-sufficient). **NOTE-1 hardening (Doc 00 §11.70 — binding for v1.4+):** the cold-quad's "cold" precondition is made **explicit and mandatory** as a written step, *not* merely the word "cold":

> **MANDATORY STEP 0 (NOTE-1 / §11.22 / §11.30):** **before** any full-workspace gate, run **`cargo clean -p` of ALL first-party workspace crates** — `cargo clean -p fsm-diagnostics -p fsm-lexer -p fsm-parser -p fsm-ir -p fsm-analyzer -p fsm-codegen-c -p fsm-simulator -p fsm-formatter -p fsm-cli -p fsm-lsp -p fsm-verify` (cargo 1.75 needs the repeated `-p` form) — **then** the canonical quad. This is non-negotiable. The box-infeasible "fresh non-shared `CARGO_TARGET_DIR`" ideal is **explicitly rejected** (a virgin target rebuilds the ~14 GiB dep graph; a blind full `cargo clean` evicts the registry cache → ~14 GiB from-zero — the box runs ~6–9 GiB free, and `/` is at ~7.1G/91%).
